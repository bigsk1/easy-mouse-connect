# Design rationale and references

These references explain the main implementation choices. Upstream API documentation describes individual contracts; it does not certify the application, its security or its hardware compatibility. [Architecture](architecture.md) and [protocol](protocol.md) describe current behavior, while [development](development.md) and [manual testing](manual-testing.md) describe verification.

## Rust core and Tauri settings

Tauri separates the Rust core from WebView processes and routes IPC through the core. Native capture, cryptographic state and networking therefore remain independent of settings rendering. Vanilla HTML/CSS/JavaScript provides the settings interface without a frontend framework or build step. This does not eliminate WebView2 or the Rust dependency graph. [Tauri process model](https://v2.tauri.app/concept/process-model/)

Capabilities and content-security policy limit frontend authority. The settings WebView loads local resources and calls specific Rust commands with validated inputs instead of receiving general shell/filesystem authority. [Tauri capabilities](https://v2.tauri.app/security/capabilities/), [Tauri CSP](https://v2.tauri.app/security/csp/)

## Windows capture and relative movement

`SendInput` is subject to User Interface Privilege Isolation: injection is permitted only at equal or lower integrity. The application consequently targets the ordinary user desktop. A service, elevated companion or UIAccess design would change its security architecture and is outside the current scope. [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

Windows can silently remove a low-level hook after a callback timeout. Callbacks must return promptly and pass work onward rather than performing networking, disk output or rendering. Background raw relative mouse input supplies movement, while low-level hooks provide suppression, keyboard capture and emergency release. Sustained raw activity without callback delivery can suggest hook failure, but installation success and idle gaps cannot establish liveness. [Microsoft LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc), [Microsoft LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [Microsoft raw input overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)

The raw-device and hook contracts do not guarantee a one-to-one relationship or ordering under suppression. `RAWMOUSE` permits coalesced movement; equal millisecond timestamps do not establish packet identity. The source guard therefore observes continuing accepted physical relative progress with bounded raw-first tolerance and a missing-progress release deadline. Registration, native epochs, queue bounds and original event ages remain independent guards. [Microsoft RAWMOUSE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse), [Microsoft GetMessageTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)

Relative capture/insertion avoids reconstructing motion from a virtual-desktop center or reading cursor positions before prior absolute injections apply. Windows applies receiver pointer settings to relative injection; identical motion speed across different settings is not guaranteed. Occupied monitor rectangles, rather than the bounding box alone, determine valid entry/return geometry. [Microsoft MOUSEINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-mouseinput)

Source entry samples `GetCursorPos` once during physical relative raw processing and accumulates outward X pressure at the same eligible edge span. A preceding hook callback or fresh hook timestamp is not required: after Windows clamps the pointer at an edge, further raw pressure must still be able to authorize entry. Zero/tangent packets preserve valid partial pressure, while inward or invalid-site observations clear it. [Microsoft GetCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos), [Microsoft raw input model](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)

## Raw registration and message scheduling

Only the last registered window for a raw-device class receives that class within one process. Tauri/Tao device-event registration must therefore be disabled before the application backend registers its hidden window. Later audits check the target and compatible delivery flags. Windows readback can omit `RIDEV_DEVNOTIFY`; requiring exact flag echo would reject a valid registration. Unavailable inspection is distinct from a confirmed mismatch and cannot justify blind registration. [Microsoft RegisterRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices), [Microsoft GetRegisteredRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getregisteredrawinputdevices), [Microsoft RAWINPUTDEVICE flags](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice), [Tauri 2.12.4 filter API](https://docs.rs/tauri/2.12.4/tauri/struct.App.html#method.set_device_event_filter)

Posted messages precede hardware input and timers in an unfiltered message loop. A bounded channel with a continuously refilled drain can still starve input. The native pump coalesces wakes, bounds work by count and elapsed time, services input between slices and preserves an already-retrieved message's order. Original receipt deadlines continue through queueing; a ready future cannot extend the budget merely because a timeout was polled late. [Microsoft GetMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessage)

Low-level keyboard asynchronous state updates after the callback. Held-state reconciliation consequently runs outside callbacks and applies only to local pass-through holds. Suppressed-origin holds require an observed release or device reset; a cleanup keyup is not evidence of local intent to reclaim. [Microsoft LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)

## Ordered input insertion and scrolling

PowerToys Mouse Without Borders' input-simulation helper warns about possible `SendInput` deadlocks when called from the hook-procedure thread and uses a separate serialized caller context. Along with Microsoft's prompt-hook guidance, this supports keeping all insertion on one bounded ordered executor outside the hook/raw thread. It is engineering precedent, not proof that every observed delay has that cause. [PowerToys Common.cs input-simulation helper](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/modules/MouseWithoutBorders/App/Core/Common.cs#L450-L461), [Microsoft LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)

The executor preserves actual-completion acknowledgment, original receipt deadlines, action barriers and ownership cancellation. It records accepted key/button downs so cancellation racing OS acceptance can release late holds before replacement input. A blocked OS call cannot be interrupted, and starting another executor beside it would break ordering. Insertion-backend duration counters include thin wrappers/coordinate work; they are not an exact syscall or end-to-end rendering measurement.

Raw wheel data is a signed short. Windows permits deltas smaller than the 120-unit wheel increment for fine-resolution devices, leaving target applications to accumulate or respond partially. Forwarding preserves signed magnitude and axis instead of replacing small deltas with full notches or discarding them as movement jitter. Wheel, key and button events remain ordering barriers. [Microsoft RAWMOUSE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse), [Microsoft WM_MOUSEWHEEL](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mousewheel)

## Cursor visibility and shapes

Mouse Without Borders documents cursor drawing for an absent physical pointer and relative movement for display differences. Easy Mouse Connect uses a receiving-only fallback when the OS cursor is unavailable, without changing global cursor settings. [PowerToys Mouse Without Borders settings and known issues](https://learn.microsoft.com/en-us/windows/powertoys/mouse-without-borders)

Visibility and artwork are separate `CURSORINFO` fields. The renderer preserves valid hidden resize/text shapes, copies owned artwork with native hotspots and paints on its own thread. A requested 8 ms timer is subject to the documented 10 ms `USER_TIMER_MINIMUM` and scheduling; movement-triggered coalesced wakes avoid relying on it for normal updates. Ordinary movement uses `SWP_NOZORDER`. [Microsoft CURSORINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-cursorinfo), [Microsoft SetTimer](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-settimer), [Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)

An ordinary topmost overlay has no universal shell, Start/Search or full-screen coverage guarantee. Administrator mode alone does not confer UIAccess, which has a separate signed/secure-install accessibility trust model. Source-pointer hiding remains unimplemented because selecting another application's cursor and preserving first-click delivery requires a safe input-ownership design. [Microsoft UIAccess](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview), [Microsoft SetCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcursor)

## Transport, pairing and routes

The Noise framework defines static/ephemeral handshake patterns and optional PSK modifiers. The application uses XXpsk3 after short-code bootstrapping and IK for pinned identities. Snow implements those patterns; the application still owns framing, resource limits, lifecycle and authorization. [Noise specification](https://noiseprotocol.org/noise.html), [Snow documentation](https://docs.rs/snow/latest/snow/)

Twelve uniformly sampled base32 characters provide 60 random bits. A five-minute lifetime and five-attempt budget bound online code use. RustCrypto SPAKE2 0.4 derives a shared secret from fixed role identities and the code; transcript-bound HKDF-SHA256 supplies the Noise PSK, and the same transcript enters the Noise prologue. Directly hashing the code would not provide this PAKE bootstrap. Upstream documents audit/timing limitations, so neither the dependency nor this integration is described as independently audited. [RustCrypto spake2 0.4 documentation](https://docs.rs/spake2/0.4.0/spake2/), [protocol details](protocol.md)

Separate control/bulk TCP streams keep file bytes out of input queues. `TCP_NODELAY` avoids Nagle buffering of small messages, but ordered retransmission can still delay events after loss. A transport change needs measurements identifying a bottleneck and its compatibility/security implications. [Rust TcpStream::set_nodelay](https://doc.rust-lang.org/std/net/struct.TcpStream.html#method.set_nodelay)

Routing and firewall policy determine reachability, independently of matching IPv4 prefixes. Tailscale supplies an existing route between sites while application authentication/encryption remain enabled. Direct, DERP-relayed and peer-relayed paths can have different latency/throughput; inspect the actual path before attributing stutter to native input. [Tailscale device connectivity](https://tailscale.com/docs/reference/device-connectivity), [Tailscale connection types](https://tailscale.com/docs/reference/connection-types)

## Packaging, diagnostics and portability

Windows builds require Rust MSVC, Microsoft C++ Build Tools/SDK and WebView2. The npm Tauri CLI is a development dependency. NSIS packages per-user Windows installations; signing/provenance are release work. [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/#windows), [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/)

The native tray and single-instance plugin provide background operation: Close hides, Quit stops, and another launch restores the existing window. Tray code remains in Rust without general shell authority for the WebView. [Tauri system tray](https://v2.tauri.app/learn/system-tray/), [Tauri single-instance plugin](https://v2.tauri.app/plugin/single-instance/)

Diagnostics use typed events instead of free-text errors. A nonblocking queue feeds three 2 MiB rolling files. Explicit export reparses allowlisted records and numeric/boolean summaries into one replaceable local ZIP. This keeps retention bounded while excluding identifying strings, input histories and shared content; it cannot reconstruct every failure.

The Rust protocol and session policy are portable, but Linux desktop input is separate work. Wayland capture/emulation is mediated by compositors and permission portals. Ubuntu support requires a compositor-approved backend and GNOME/Wayland acceptance, not only a Linux compile result. [XDG InputCapture portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.InputCapture.html), [libei protocol](https://libinput.pages.freedesktop.org/libei/)
