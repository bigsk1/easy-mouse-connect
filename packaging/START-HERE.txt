EASY MOUSE CONNECT 0.4.1 - WINDOWS X64 PREVIEW

Share a mouse and keyboard between two explicitly paired Windows PCs.
Connections require encryption and a trusted device identity.
Download matching installer/source/checksums from GitHub Releases. Install the
same 0.4.1 build on BOTH PCs for the fixes. Versions 0.4.0/0.4.1 share EMC02;
neither connects to 0.3.7. Existing identities and pairing are retained. Do not Forget device merely to update.
Source and support: https://github.com/bigsk1/easy-mouse-connect

INSTALL AND OPEN
Install the preview locally on each PC, or run a local copy of the portable
executable. The installer is per-user, needs no administrator privileges,
and offers an optional desktop shortcut. Open the app from Start or that
shortcut. A second launch restores the existing instance.

Microsoft Edge WebView2 Runtime is required. Rust and Node are not required
to run the app. If WebView2 is absent, install Microsoft's Evergreen runtime:
https://developer.microsoft.com/en-us/microsoft-edge/webview2/

Each PC creates its OWN protected identity under:
%LOCALAPPDATA%\EasyMouseConnect
Never copy identity.dat, pairing credentials or runtime settings between PCs.

PAIR THE PCS
1. Keep local mouse/keyboard input available on both PCs. Use the same app
   version on each. Make the receiver's IP reachable on TCP port 24859.
2. On PC B open Devices > Pair a device > Show a pairing code > Generate code.
3. On PC A choose Connect to a device, enter B's reachable IP, and TYPE B's
   12-character code, displayed as XXXX-XXXX-XXXX. Spaces/hyphens are optional
   and letter case is ignored. Click Pair devices. No shared clipboard or
   invitation file is needed.
4. The code expires after five minutes and admits at most five attempts;
   failed or abandoned attempts count. Generate a fresh code after either
   limit. Keep the code private.
5. Set Peer on left/right on each PC for the other PC's position. The two
   settings should be opposite. Enable desk sharing and Move across screen
   edges. Test Ctrl+Alt+Escape locally before relying on remote control.
6. Release held local keys/buttons and push outward through the configured
   exposed side edge of a monitor, away from corners. Moving between monitors
   on the same PC stays local. Windows display rectangles determine the edges,
   including stacked/portrait layouts, negative coordinates and gaps.

The PC that ENTERED the code dials automatically every three seconds while
sharing is enabled. Use Reconnect there; the code-generating PC listens.

Different LAN subnets require routing. Across locations, use an existing VPN
such as Tailscale with both peers online, authorized and allowed by policy.
Entering an IP does not create a route or a VPN. The app does not open firewall
rules automatically. If needed, open Troubleshooting, enter one peer IP and
click Add a firewall rule. Approve the Windows prompt with local controls.
A fixed helper adds an inbound rule for this executable, the exact peer and
TCP 24859 on Private/Domain profiles only. The app itself remains unelevated.
Cancelling approval changes no rule. The action creates no route/VPN and does
not open Public networks. See docs/networking.md for scope/removal and the
script-based helper. Do not disable Windows Firewall or expose the
listener through internet port forwarding to make a connection work.

DAILY CONTROLS
Move back through the shared edge to return, or press Ctrl+Alt+Escape on the
controller to release. Genuine physical input on the receiver can also reclaim
control. Receiver movement has a small jitter threshold; keydown, buttons and
wheel reclaim immediately. Keep mouse/keyboard hardware connected to the PC
you intend to use as controller.

Closing the window hides it in the tray. Tray Open, a tray click or a second
launch restores the window. Pause/Resume changes sharing availability;
Stop sharing pauses and releases input. Quit Easy Mouse Connect exits the app.
Forget device revokes trust and requires fresh explicit pairing to restore it.

If a Bluetooth keyboard stops responding, confirm its selected host matches
the intended controller. Reselecting that host restored one reported 0.4.1
interruption; its cause is unconfirmed. If it repeats, record ownership/direction
and collect both diagnostic ZIPs without including typed content.

A protected held key/button can block crossing after a device or desktop
switch. Release the actual control. If its UP was missed, press and release
the affected modifier/button locally when prompted. The sender's pointer
currently remains parked at its edge while routing remotely.

CLIPBOARD AND FILES
Each feature starts OFF. Enable each desired permission on BOTH PCs in Sharing.
Text, images and app-based files have separate permissions. Copy a NEW value
after connecting/enabling; the old clipboard is not sent immediately.

Plain-text clipboard supports up to 1 MiB of UTF-8: roughly one million ASCII
characters, fewer for multibyte text. Pairing-code-shaped text and legacy
invitations are excluded from text sync.

Image clipboard accepts screenshots, supported bitmaps and one copied local
PNG/JPEG/static WebP image file. It converts the image to PNG without an extra
recipient prompt after image sharing is enabled. It does not preserve the
original filename/format. Use Send file when you need the original file.

Limits:
- Copied source image file at most 16 MiB.
- Canonical PNG at most 16 MiB.
- Decoded RGBA at most 64 MiB.
- Each dimension at most 16,384 pixels.

Try Snipping Tool > Copy, context-menu Copy and Ctrl+C from supported apps,
then cross back and paste in an image-capable app. The receiver publishes
bitmap formats and a local PNG file representation for File Explorer paste.
For an Explorer source, select exactly one local PNG, JPEG/JPG or static WebP
file and use Ctrl+C or Copy. Folders, multiple-file selections, animated WebP,
UNC shares and mapped network files are unsupported. Image clipboard does not
require Allow file transfers and is not general file-copy authority.

Switching between text and images, then recopying an earlier local value,
should deliver each new permitted copy once. Received-image markers suppress
reflection when Windows requests/publishes extra formats and metadata.

Explorer compatibility retains private PNG images under:
%LOCALAPPDATA%\EasyMouseConnect\clipboard-images
At most four managed images of up to 16 MiB each are retained. They have Windows
internet-zone marking and generated names. Later updates can evict old files;
save a permanent copy elsewhere rather than depending on a cache path. Current
clipboard references are protected, so a full/unwritable cache can reject an
update. Cached image bytes are ordinary user data, not DPAPI-encrypted identity
storage. They remain private and are excluded from logs, diagnostic ZIPs and
source packages. Disabling sharing stops synchronization, not copies already
placed on a clipboard or saved by another app.

To send a file, enable Allow file transfers, drop a regular file into the app,
click Send file, and approve the offer on the receiving PC. Each file must be
SMALLER THAN 100,000,000 bytes; the exact limit and larger files are rejected.
The default receiving path is:
%USERPROFILE%\Downloads\EasyMouseConnect\<transfer-id>\<filename>
Sharing displays the receiving directory. Each transfer has its own generated
child directory, and existing files are never overwritten.

Approve within 65 seconds. The incoming transfer expires 120 seconds after
offer creation. Transfers check exact length and SHA-256 and apply Windows
internet-zone marking before the final save. The sender reports success only
after receiver confirmation. If that acknowledgment is lost, inspect the
receiver's transfer directory before retrying. Interrupted transfers do not
resume automatically. Received files are never opened or executed automatically.
Direct Explorer-to-Explorer dragging across PCs is not implemented.

PREFERENCES AND STATUS
Devices has matching Desk controls and Preferences columns. Keep the other PC
awake starts OFF and must be enabled on BOTH PCs. It prevents peer display-off
and idle sleep while you physically work on this PC. Activity stays eligible
for 30 seconds, is signaled at most every three seconds and renews a 15-second
receiver lease. Idle expiry, disconnect, Pause, Quit or disabling the option
releases the request. It does NOT block Windows screen savers, security locks,
manual sleep or organization policy. It sends no fake input and needs no service
or elevated app.

Show clipboard and network notifications also starts OFF. Clipboard messages
are receive-only, with a 30-second cooldown; local copying creates no clipboard
tray message. Network messages have a five-second cooldown. Queued events older
than five seconds are discarded, not replayed as a late burst. Messages contain
no copied text, image previews, names, IPs or paths. Windows notification
settings/Focus Assist may hide them. Missing notifications alone
do not mean a clipboard or connection failure. The Windows Preview footer opens
the fixed project GitHub repository.

DIAGNOSTICS AND REPORTS
Open Diagnostics for routing state, network checks and input/processing
counters. A low network RTT is not measured end-to-end input latency.

Local logs: %LOCALAPPDATA%\EasyMouseConnect\logs
Managed names: emc.log, emc.1.log, emc.2.log
Limit: 2 MiB each / 6 MiB total.

Logs contain typed operational events and failure categories. They exclude
raw input/keys, typed text, clipboard/file contents, credentials, file names
and paths, peer IPs and device names. Input diagnostics are aggregate counts
and durations rather than an event history.

Diagnostics > Export diagnostic ZIP creates:
%LOCALAPPDATA%\EasyMouseConnect\diagnostic-exports\emc-diagnostics.zip
Export is user-controlled and local; nothing uploads automatically. It includes
sanitized logs and numeric/boolean status, including counters and display
dimensions, without identity/settings files or local directory metadata.
Each export REPLACES that ZIP. Copy an older export elsewhere first if needed.
Use Open export folder to locate it. A rolling .log alone lacks the summary.

After a problem, collect a ZIP from each PC. Sequential collection is valid:
export A while running, Quit A, switch Bluetooth hardware if needed, export B,
then Quit B. Mention the sequence. These are separate snapshots; the first
Quit can cause an expected disconnect on the other PC. Collection transitions
do not, by themselves, establish the cause of the reported input problem.

Review ZIPs and screenshots before sharing. Include the app/Windows versions,
minimal steps, failed direction and relevant display/input configuration.
Never attach pairing codes, identity.dat, clipboard contents or user files.
Ordinary bugs: https://github.com/bigsk1/easy-mouse-connect/issues
Security concerns: use the private reporting process in SECURITY.md, or:
https://github.com/bigsk1/easy-mouse-connect/security/advisories/new

UPDATE AND UNINSTALL
Quit BOTH tray apps before installing an update, then use the same version
on both PCs. Keep identity.dat and the existing pairing. Versions 0.2.0 through
0.4.1 preserve the version-1 identity/settings format and established peer keys.
Versions 0.4.0/0.4.1 use the same EMC02 wire format; 0.3.7 cannot connect.
Use the same 0.4.1 build on both PCs for the clipboard/notification fixes.
Do not Forget device merely to upgrade.

If saving settings fails, requested Stop/Pause and file/clipboard reductions
remain active for this run; the last saved permissions may return on restart.
The error explains this. Unsaved permission increases are not applied. Use
tray Quit to keep the app stopped while resolving profile write access.

Uninstall through Windows Settings > Apps > Installed apps > Easy Mouse Connect
Preview, or its Start menu uninstall entry. Quit the tray app first.
Uninstall removes the installed app, shortcuts and registration. It preserves
identities/settings, diagnostics, received files and cached clipboard images. The portable executable
has no uninstall entry.

CURRENT LIMITS
This is an unsigned Windows 11 x64 preview. A retained local 0.4.1 build has a
maintainer report of approximately half a day of two-PC use behaving as expected.
One keyboard interruption recovered after reselecting its Bluetooth host; the
cause is unconfirmed. This normal-use report does not pass every image format,
policy boundary, fault case or hardware/network configuration.

GitHub release assets are separate CI-produced bytes from the release commit.
Their SHA256SUMS.txt identifies this package, not the earlier local test package.
The source inputs are compared with the retained tested runtime snapshot;
matching source does not mean identical executable or source-ZIP hashes. A short
downloaded-package install/reconnect/input/clipboard smoke check is follow-up
evidence, separate from both CI compilation and the local normal-use report.
The exact acceptance scope and retained local artifact hashes are documented
in docs/manual-testing.md. Earlier 0.3.7 and 0.4.0 reports keep their own scopes.

Follow docs/manual-testing.md in this source package for remaining checks.
An AI-assisted source review of an earlier baseline is not an independent
professional audit or a review of all new 0.4.1 behavior. See SECURITY.md and
docs/security-review.md for the security model and review scope.

Trust only PCs you intend to control your signed-in desktop. Pairing uses a
short-lived code and SPAKE2 before Noise identity exchange; transport has no
plaintext fallback. Existing pinned identities survive this update; an old
legacy invitation is never an automatic fallback.

Windows 11 x64 user-session input is the desktop target. UAC, the lock screen,
secure desktops and elevated application control are outside supported scope.
The app installs no service, runs unelevated and changes no global cursor
settings. Only the explicit peer-scoped firewall helper requests Windows
administrator approval. It grants no secure-desktop control. Keep UAC enabled.

Shell/fullscreen surfaces can cover the receiving cursor fallback. Intentional
app cursor hiding may be overridden by that fallback. Source-pointer hiding,
exact vertical return-position preservation, automatic discovery/NAT traversal and direct Explorer file dragging are not implemented.
Vendor gestures and remapped/injected macros are not guaranteed. Unsupported
absolute raw devices release control. Stale input, queue overload or native
failure disconnects/releases instead of replaying backlog; the local budget
remains 200 ms. Linux desktop input is not implemented.

See README.md and docs/troubleshooting.md in the source for setup and help;
docs/development.md describes developer checks. SHA256SUMS.txt identifies
matching package bytes, not a signed publisher or a reproducible build.
